## 二、问题分类

### Problem A：空值与 activation 矛盾（623 文件）

word_root 为空但 network_activation 仍含"词根"。

**影响范围**：623 / 631 个空值文件（98%的空值文件有此问题）

**示例**：
- `abandon.md`：word_root 为空（词源是日耳曼语复合，无典型拉丁词根），但 na 含"词根"
- `oath.md`：word_root 为空（无词根词缀 section），但 na 含"词根"
- `and.md`：word_root 为空（功能词），但 na 含"词根"

**修复方案**：word_root 为空时，从 network_activation 中移除"词根"

#### B-3：错误提取（~519 文件）

word_root 填的是**同源词、形近词、整个词**，不是词根。

**错误模式**：

| 模式 | 示例 | 应修正为 |
|------|------|---------|
| 同源词当词根 | receipt → `receive`, imagine → `imitate` | receipt → `cap`/`cap-ceiv-capt`, imagine → 空 |
| 形近词当词根 | though → `thought` | → 空（功能词无词根） |
| 前缀的派生词当词根 | category → `catastrophe` | → `cata`（前缀）或空 |
| 拉丁完整词当词根 | merchant → `mercari` | → `merc`（如有）或空 |
| 复合词成分当词根 | workforce → `work` | → 空（复合词非词根派生） |
| 整个词当词根 | outward → `appearance` | → 空（out-+ward，无词根） |

**确认方法**：正文中 `[[词根名]]` 的 wikilink 被错误地提取为 word_root，而 `[[词根名]]` 指向的往往是**同源词**而非词根本身。

**长值(>8字符)案例**：
- `Akademeia` (academic)、`catastrophe` (category)、`receive` (receipt)
- `scrib-script` (3)、`pel-puls` (2)、`cre-cresc-cret` (2) → 这些反而是正确的复合词根名，只是词根目录中没有对应页面

### Problem C：孤儿词根（17 / 100）

词根目录中存在但无任何单词卡指向的词根页面：

`ab`, `ana`, `circ`, `cor-cord`, `de`, `inter`, `min-mini`, `mon-monstr`, `ob`, `ped-pod`, `per`, `sub`, `super`, `syn-sym-syl-sys`, `trans`, `under`, `up`

> [!note] 说明
> 这些词根多为前缀（de-, sub-, inter- 等），它们以"前缀+词根"组合出现在单词卡中，而 word_root 只记录了核心词根，不含前缀。这是合理的——前缀应在前缀页面处理，不需要在单词卡的 word_root 中体现。

## 三、根因分析

B0 回填的 word_root 提取逻辑存在**系统性缺陷**：

1. **从正文的 `[[wikilink]]` 中取值**，而非从构词分析中提取词根形素
   - 导致：`[[receive]]` → word_root=receive（同源词，非词根）
   - 导致：`[[catastrophe]]` → word_root=catastrophe（派生词，非词根）

2. **未对齐词根目录的命名规范**
   - 目录用复合名：`miss-mit`, `spec-spect`, `ced-cess`
   - 卡片用单个形素：`mit`, `spec`, `cess`
   - 两者之间缺少规范化映射

3. **未区分"有词根"和"无词根"**
   - 复合词（workforce）、功能词（and, though）、日耳曼本族词（oath）不应有 word_root 值
   - 但回填时几乎全部标记了"词根"在 network_activation 中

4. **word_root 和 network_activation 填充逻辑互相独立**
   - word_root 为空时，network_activation 仍含"词根"

## 四、修正方案

### Phase 1：机械修正（立即可执行）

**1a. 修正 Problem A**：623 个文件
- 规则：word_root 为空 → 从 network_activation 移除"词根"

**1b. 修正 Problem B-3 长值错误**：~519 个文件
- 规则：word_root 值 > 8 字符且不含连字符且不在词根目录 → 清空 word_root 并移除 na 中的"词根"
- 例外：复合词根名如 `scrib-script`, `pel-puls`, `cre-cresc-cret` 应保留

### Phase 2：词根规范化映射（需构建映射表）

**2a. 构建权威映射表**
- 来源 1：词根目录文件名的连字符拆分（`miss-mit` → `miss` 映射到 `miss-mit`, `mit` 映射到 `miss-mit`）
- 来源 2：词根文件的 aliases 字段（`spec-spect.md` 有 aliases: [spec, spect, spic, spit]）
- 来源 3：词根文件 title 中的变体名（`cap.md` 的 title 含 "capt-/ceiv-/cept-"）

**2b. 用映射表修正 B-2 类文件**
- 对每个 word_root 值查映射表
- 精确命中 → 自动替换为规范名
- 未命中但看起来像词根（≤6字符，纯小写拉丁字母）→ 标记为"待创建词根页面"
- 未命中且看起来像英语单词 → 清空

### Phase 3：network_activation 全面修正

- word_root 非空且在词根目录有对应 → 保留"词根"
- word_root 非空但不在词根目录 → 移除"词根"（等词根页面创建后再加回）
- word_root 为空 → 移除"词根"
