# Trae Wiki 层重建 — 主调度指令

> **用途**：在 Trae 网页版 Solo MTC 模式中，分批执行 Wiki 层重建
> **执行顺序**：B0 → B1 → B2 → B3 → B4 → B5（严格按序，每批有前置依赖）

---

## 使用方法

1. 打开 Trae 网页版，选择 Solo MTC 模式
2. 打开项目目录 `E:\Notes\obsidian-eg`
3. 从 B0 开始，将对应的【批次指令】粘贴到对话框
4. 将对应的【规范文件】作为附件/引用提供给 Trae
5. 每批完成后确认结果，再执行下一批

---

## 依赖关系

```
B0（Raw字段回填）
 ├──→ B1（C级词根重写）──→ B2（B级词根升级）
 ├──→ B3（语义场升级）
 └──→ B4（形近字生成）
      └──→ B5（双向链接确认）
```

- B0 是所有后续任务的前置
- B1 和 B2 有先后（C 级先处理）
- B3 和 B4 可以并行（但都需要 B0 完成）
- B5 是最后的收尾

## B0：Raw 字段回填

### 规范文件
`Wiki/_系统/_Trae-B0-Raw字段回填规范.md`

### 指令

```
你是一个 Obsidian 词汇知识库的批量修正工具。请严格按照《B0-Raw字段回填规范》对单词笔记的 frontmatter 执行字段回填。

### 工作范围
- 目录：Wiki/L0_单词集合/、Wiki/L0_基础词/、Wiki/L0_超纲词/
- 文件类型：仅处理 .md 文件
- 每批处理 200 个文件，完成后报告结果再继续

### 本次任务
仅修改 frontmatter 中的两个空/不一致字段：
1. **word_root 回填**：从正文"词根词缀"section 中提取词根名，写入 word_root 字段
2. **network_activation 回填**：根据正文各 section 的实际内容，程序化判定激活类型

### 关键规则
1. **不修改正文**——本次任务仅修改 frontmatter
2. **word_root 提取优先级**：wikilink → 词源关联段落 → 留空
3. **word_root 验证**：提取值必须在 Wiki/词根词缀/ 目录下有对应 .md 文件，否则追加 ⚠️
4. **network_activation 判定**：word_root非空→词根，同义词表非空→同义辨析，反义词非空→反义词群，派生词非空→派生词族
5. **已有值不覆盖**

### 输出格式
每批完成后输出：
- 处理文件数
- word_root：匹配已有页面数 / ⚠️待建数 / 留空数
- network_activation：四种激活类型的命中数
- ⚠️ 待建词根页面清单（去重列表）

### 参考文件
- 回填规范：Wiki/_系统/_Trae-B0-Raw字段回填规范.md（已附在本对话中）

现在开始处理第一批（按文件名字母序，取前 200 个 .md 文件）。
```

### 验证指令

```
随机抽查 10 个文件（从三个目录各取 3-4 个），验证：
1. word_root 字段是否已从正文正确提取
2. network_activation 是否根据正文内容正确判定
3. 正文内容未被修改
输出验证结果，标注任何不符合的文件和具体问题。
```

### C 级页面判定
文件大小 < 2.5KB 的词根 .md 文件（跳过 _模板-词根笔记.md）

### 重写规则
1. **叙事记忆扩充**：从 word_root 指向该词根的所有单词卡中提取词源叙事

### 关键规则
- 不要编造不存在的派生词
- 不要修改单词卡（raw 层）
- 不要删除现有叙事
- 含义延伸链路中只收录知识库中实际存在的词

### 参考文件
- 升级规范：Wiki/_系统/_Trae-B1B2-词根页面升级规范.md（已附）
- 参考标杆：Wiki/词根词缀/spec-spect.md（4.61KB，质量最高的页面）

## B4：形近字页面生成

### 规范文件
`Wiki/_系统/_Trae-B4-形近字生成规范.md`

### 指令

```
你是一个英语词汇教学专家。请按照《B4-形近字生成规范》生成形近字辨析页面。

### 工作范围
- 目标目录：Wiki/形近词/
- 生成约 50-80 个形近字辨析页面

### 执行方式

#### 阶段一：扫描聚类
1. 收集全部 5249 个单词名
2. 计算两两编辑距离（Levenshtein ≤ 2）
3. 按判定逻辑过滤假阳性
4. 输出词组清单

#### 阶段二：页面生成
按照审核后的词组清单逐组生成，格式见规范文件。

### 形近字判定逻辑（按优先级）
1. **前缀/后缀互换**（最高优先级）：adapt/adopt/adept, affect/effect
2. **词根变体**：spec/spect/spic
3. **拼写高度相似**（编辑距离 ≤ 2）：complement/compliment
4. **音近误混**（仅高频）：weather/whether

### 排除规则
- 仅有共同前缀/后缀但词根不同 → 不算形近字
- 词长差距 > 3 → 不算形近字

### 页面格式
- 小群组（2-4词）：对比表 + 故事串联记忆
- 大群组（5+词）：词根核心 + 全局对比表 + 故事串联记忆

### 参考文件
- 生成规范：Wiki/_系统/_Trae-B4-形近字生成规范.md（已附）
- 预判高频组：见规范文件第五节
- 关联单词卡：从各词的 raw 卡中提取词源/原型义/记忆锚点

请先执行阶段一（扫描聚类），输出词组清单供审核后再生成页面。
```

## B5：双向链接确认

### 指令

```
请对知识库执行双向链接一致性检查和修复。

### 检查项
1. **词根双向链接**：
   - 单词卡的 word_root 指向词根页面 → 词根页面的派生词族要包含该单词
   - 词根页面"相关词根"中链接的词根 → 被链接的词根页面也要链接回来

2. **语义场双向链接**：
   - 单词卡的 semantic_field 指向语义场页面 → 语义场页面的 Dataview 查询能检索到该词
   - 语义场页面"跨场关联"中链接的场 → 被链接的场页面也要链接回来

3. **形近词双向链接**：
   - 形近词页面中 [[wikilink]] 的词 → 确认对应的单词卡存在
   - （可选）在单词卡 frontmatter 中新增 confusable_group 字段

### 输出
- 断链数量及位置
- 单向链接数量及位置（A→B 但 B 不→A）
- 缺失词条清单
```
