## 二、升级规则

### 2.1 叙事记忆扩充

**输入来源**：通过 `word_root` 字段筛选所有关联的单词卡，阅读其"词根词缀"和"记忆锚点"section。

**扩充规则**：

1. **每个高频派生词必须有叙事**——高频判定：出现在考研核心词表中的词
2. 叙事格式统一为：

```markdown
[[word]]：前缀(含义) + 词根(含义) + 后缀(含义) → **一句话核心画面**。展开叙事：从原始画面到引申义的场景迁移。叙事遵循 5 标准：具象/情感/简洁/关联/独特。
```

3. **叙事必须围绕词根核心义展开**——重点是"前缀如何改变了词根的方向"
4. **叙事不要重复单词卡内容**——词根页的叙事是"从词根视角看的词源故事"，单词卡的叙事是"从单词自身看的记忆锚点"，视角不同
5. **已有叙事不删除**——只补充，不覆盖

**反面示例**（graph-gram.md 的问题）：
```
| [[character]] | graph-/gram- | 性格，品质 |
| [[paragraph]] | graph-/gram- | （文章的）段落 |
```
→ 词根拆分列全部写"graph-/gram-"，没有真正拆分，这是不可接受的。

**正面示例**（spec-spect.md 的风格）：
```
[[respect]]：re-（回）+ spect（看）→ 回头看（带着敬意地注视）→ 尊重
```

### 2.2 含义延伸链路（B/C级缺此 section，必须新增）

这是词根页面的核心分析，展示词根义如何通过不同前缀产生分化。

**格式**（参考 spec-spect.md）：

```markdown
## 含义延伸链路

> [!note] 环境模型
> **核心义**（词根原义） → **延伸1**（前缀A + 词根 → 含义A） → **延伸2**（前缀B + 词根 → 含义B）→ ...

核心义"XXX"是一切延伸的起点：前缀A + 词根是 XXX，前缀B + 词根是 YYY，...每个前缀都改变了词根的方向/程度/对象，衍生出不同的含义。
```

**构建规则**：

1. **以词根核心义为起点**（如 spec- 的核心义是"看"）
2. **按前缀方向排序**：
   - 空间方向优先：内(in-) → 外(ex-) → 上(super-) → 下(sub-) → 前(pro-) → 后(re-) → 间(inter-)
   - 然后程度/方式：否定(dis-/un-) → 加强(ad-/de-) → 共同(con-)
3. **每个延伸必须是知识库中实际存在的词**——不要编造派生词
4. **延伸链路的最后一行**是 2-3 句总结性文字，概括前缀分化的规律

**示例**：

```markdown
## 含义延伸链路

> [!note] 环境模型
> **看**（specere，核心动作） → **看清种类**（spec- → special/specific） → **向内看**（in- + spect → inspect） → **回头看**（re- + spect → respect） → **向前看**（pro- + spect → prospect） → **在下面看**（sub- + spect → suspect） → **透过看**（per- + spect → perspective） → **向外看**（ex- + spect → expect）

核心义"看"是一切延伸的起点：看清楚种类是 special/specific，向内看是 inspect，回头看是 respect，向前看是 prospect，在下面看是 suspect，透过看是 perspective，向外看是 expect。每一个前缀都改变了"看"的方向和方式，衍生出截然不同的含义。
```

### 2.3 派生词族扩充

**扩充规则**：

1. 从所有 `word_root` 关联的单词卡中收集派生词
2. **每个词必须有真正的构词分析**——格式：`前缀(含义) + 词根(含义) + 后缀(含义)`
3. 知识库中有独立笔记的词用 `[[wikilink]]`，没有的用纯文本
4. 按构词复杂度排序：简单派生（词根+后缀）→ 复合派生（前缀+词根+后缀）
5. **去掉重复条目**（如 vis-vid.md 中 visual 出现两次）

**表格格式**：

```markdown
| 单词 | 构词分析 | 释义 |
|------|---------|------|
| [[visible]] | vis-(看) + -ible(可被…的) | 可见的 |
| [[invisible]] | in-(不) + vis-(看) + -ible(可被…的) | 看不见的 |
| [[supervise]] | super-(从上) + vis-(看) + -e | 监督，管理 |
```

**补充说明 callout**（对构词分析需要额外解释的词）：

```markdown
> [!note] 补充说明
> - [[special]]：spec- 在此取"种类/外观"义（与 species 同源），"属于某种特定种类的"→ 特别的
```

**更多同族词 callout**（知识库中暂无独立笔记的词）：

```markdown
> [!note] 更多同族词（暂无独立笔记）
> - **respect**：re-（回）+ spect（看）→ 回头看（带着敬意）→ 尊重
```

### 2.4 相关词根

**规则**：

1. 列出语义相近或词源相关的其他词根
2. **必须说明关系类型**：
   - `同义`：含义相同但词源不同（如 spec-/spect- 和 vis-/vid- 都是"看"）
   - `反义`：含义相反（如 pro- 和 re- 在方向上相反）
   - `词源同源`：来自同一原始印欧语词根
   - `语义互补`：含义相关但不相同（如 sign- 和 vid- 都涉及"使可见"）
   - `常搭配`：常在同一词中出现的前缀/后缀
3. **所有相关词根必须用 [[wikilink]] 链接**
4. **双向一致性**：如果 A 页面链接 B，B 页面也要链接 A

**格式**：

```markdown
## 相关词根

- [[vid-vis]]（同义）：与 spec/spect 同义，都表示"看"，spec- 侧重"注视"，vis- 侧重"看见"
- [[ver-vert]]（语义互补）：version（翻转→版本）与 spec- 的 species（种类→版本变体）语义相关
```

# techn-（技艺/技术）

> [!info] 核心信息
> - **词根/词缀**：techn-
> - **含义**：技艺、技术、手艺
> - **来源**：希腊语 *tekhnē*（技艺、手艺、工艺），原始印欧语 *\*teks-*（编织、建造）
> - **类型**：词根

## 叙事记忆

> [!tip] 词源故事
> 古希腊人把织布、造船、治病的技能都叫做 *tekhnē*——不是抽象的"技术"，而是**手上能做出来的东西**。一个木匠的 tekhnē 是造出结实的桌子，一个医生的 tekhnē 是治好病人的病，一个诗人的 tekhnē 是写出动人的诗句。从"手艺"到"技术"再到"科技"，techn- 走了一条从手到脑的路——但核心始终是"把知识变成实际能做到的事"。

[[technology]]：techn-(技艺) + -logy(对…的系统研究) → **对技艺的系统研究**。古希腊人把织布、造船、治病的技能都叫 *tekhnē*，后来人们开始"系统地研究"这些技艺——于是有了 technology。从古代的冶金术到今天的人工智能，technology 始终是"科学知识在实践中的应用"。

[[technique]]：techn-(技艺) + -ique(方式/风格，法语后缀) → **做某事的特定方式**。同样是画画，印象派和古典派的 technique 不同——**技艺的具体执行方式**就是 technique。技术是"能做什么"，技巧是"怎么做"。

[[technical]]：techn-(技艺) + -ical(形容词后缀，与…有关的) → **与技艺有关的**。technical 问题是"技术层面的"问题，technical terms 是"专业术语"——都指向"需要特定技艺才能理解的"。

[[technician]]：techn-(技艺) + -ician(…的人) → **掌握技艺的人**。科学家研究理论，工程师做设计，而 technician 是**实际操作的人**：操作实验室设备、绘制设计图、维护机器。他们是技艺的实践者。

---

## 含义延伸链路

> [!note] 环境模型
> **技艺**（tekhnē，手艺/技能） → **技艺的研究**（techn- + -logy → technology，科技） → **技艺的方式**（techn- + -ique → technique，技巧） → **技艺的从业者**（techn- + -ician → technician，技师） → **技艺的属性**（techn- + -ical → technical，技术的/专业的）

核心义"技艺"是起点：研究技艺是 technology，执行技艺的方式是 technique，做技艺的人是 technician，属于技艺范畴的是 technical。从"手上能做的事"出发，techn- 的派生族覆盖了知识→实践→人→属性四个维度。

## 五、执行规则

### 5.1 处理顺序

1. **先处理 C 级**（最需要重写，效果最明显）
2. **再处理 B 级**（需要升级）
3. **最后 A 级**（仅需微调）

### 5.2 每个词根页面的输入

升级时需要阅读：
1. 当前词根页面内容
2. 所有 `word_root` 指向该词根的单词卡（读取其"词根词缀"和"记忆锚点"section）
3. 相关词根页面（检查双向链接一致性）

### 5.3 禁止事项

- **不要删除现有叙事**——只补充，不覆盖
- **不要编造不存在的派生词**——每个词必须有真实词典依据
- **不要修改单词卡（raw 层）**——本次任务仅修改词根页面
- **不要改变 frontmatter 的 title 格式**——保持 `词根名（含义）` 的格式
- **不要在含义延伸链路中加入知识库中不存在的词**——如果词在库中无笔记，放在"更多同族词"callout 中

### 5.4 输出报告

每批完成后输出：
1. 处理的词根页面数量
2. 每个页面的升级前后行数/大小对比
3. 新增的含义延伸链路数量
4. 补充的叙事记忆数量
5. 发现的双向链接不一致问题
